# Elemenx Public API

This document is the release-level map of the supported top-level Elemenx surface. Detailed behavior remains covered by the regression suite and the maintained examples.

## Runtime surface

- `Elemenx.Application` — application registration, ownership, mounting and lifecycle.
- `Elemenx.Component` — component definitions, templates, styles, state, bindings and lifecycle. The values of a definition are the first state of each instance: a plain object or an array is copied, deep, for every instance (two instances never share `Items: []`), anything else (a Date, a Map, an element, an object of a class) is kept as it is. The state is reactive to a key added, taken away (`Object.keys`, `in`) and to an array made shorter by its `length`.
- `Elemenx.Template` — named Template Registry populated by DOM `<template id>` and `<script type="text/html" id>` resources (the latter keep the case of Component names, which the parser of a `<template>` lowers; Components in a `<template>` are found in any case unless their name is an HTML element) or application loaders; supports get/set, loaders and live `Reload`. The same registry is exposed as `Application.$Template`; Components and Services access it through `this.$Application().$Template(...)`. Component template metadata is `$Template`, so ordinary `Template` belongs to application code.
- `Elemenx.Directive` — custom behavioral directives and their lifecycle.
- `*lazy` — a built-in structural directive: its host (a component or an element) renders when it comes within a screen of the viewport or when the browser is idle, whichever is first, one host at a time in the order of the page, and then stays (a placeholder, `[data-elemenx-lazy]`, holds its place meanwhile: a line high, or by its value a height (`*lazy="320"` pixels, `*lazy="'20rem'"` a length; `data-elemenx-lazy="sized"`, a shimmer in ElemenxUI) or the markup of a template of the page (`*lazy="'#id'"`, `Elemenx.Template`; `data-elemenx-lazy="template"`)). A long page shows its first screen at once and builds the rest in the background instead of freezing the tab until all of it is built. A host whose component goes before its turn never renders. What the host declares exists only once it renders: its hotkeys, its listeners and its services start then, so a list of them follows their changes (`Hotkeys.OnChange` of ElemenxUI) rather than reading them once. The context of a structural directive gives `Marker`, the node that marks the place of its host.
- `Elemenx.Service` — named services, including Application-owned instances.
- `Elemenx.Guard` — named route guards used by Application routing.
- `Elemenx.Router` — routing and browser-history facade.
- `Elemenx.Network` — transports, protocols, transfer helpers and network contexts.
- `Elemenx.Storage` — storage providers and composable storage contexts.
- `Elemenx.Events` — synchronous same-runtime event channels.
- `Elemenx.Messaging` — cross-context message channels and composable messaging contexts.
- `Elemenx.Meta` — what Components, Services and Directives declare of themselves for tools (a builder, a reference) in the `$Meta` key of their definitions: `{Group, Icon, Description, Props, Slots, Container, Children, Current, Events, Methods, Sample}`, where `Props` names the public props, each a description or `{Type, Options, Schema, Body, Description}` (`Schema` describes the items of a list prop, `{ID: 'text', Disabled: 'bool'}`; `Body` marks a text the component also takes from its body, which a tool writes there, as the code of a CodeView), `Children` names the components declared inside it (`Tab` in `Tabs`), `Current` the prop that names the one shown (`Value`), and `Events` the events it emits, a list of names or `{name: description}`. `Elemenx.Meta(name)` returns it normalized for the definition of that name (a Directive in any case): `{Name, Kind ('Component', 'Service' or 'Directive'), Group, Icon, Description, Props: [{Name, Type ('bool', 'number', 'text', 'select', 'json'), Default (the value of the definition), Options, Schema, Body (true or false), Description}], Slots, Container, Events (the names), EventDescriptions (`{name: description}`, `{}` for a list of names), Methods, Sample}`, a copy, or `null` when no such definition is loaded or it declares no `$Meta`; `Elemenx.Meta()` returns the ones of every loaded Component that declares one. `$Meta` is never state.
- `Elemenx.WebWorker` — Web Worker lifecycle and Messaging bridge.
- `Elemenx.ServiceWorker` — Service Worker lifecycle and registration helpers.
- `Elemenx.Bundle` — production bundle registry used before normal Discovery fallback.
- `Elemenx.Expressions(map)` — precompiled template expressions: `{source: function ($globals, $scope)}`, the function a build wrote as code for each expression of the templates (`with ($globals) { with ($scope) { return (source); } }`). The template compiler takes them before compiling, so a page whose Content-Security-Policy forbids eval (a browser extension) renders its templates; an expression missing there throws `Elemenx expression is not precompiled and the page forbids eval: <source>`. Returns `Elemenx`.
- `Elemenx.Locale` — the phrases of the Applications and their Libraries in the language of the page, by key. `Language()` returns the language, `Language(code, callback)` loads its dictionaries and then switches to it (the `lang` and `dir` of the page follow) and remembers it (`localStorage` `elemenx-language`; not in an isolated build), `Language('system', callback)` forgets it and takes the language of the system; `System()` is the language of the system (the first of `navigator.languages` the Applications have, as it is or by its base) or `null`; an Application whose `$Locales` is `{URL, Languages}` starts in the language chosen before when it has it, else in the one of the system among its `Languages`, else in the `lang` of the page (`$Locales.System: false` keeps the `lang` of the page); `Fallback(code)` (`en` by default); `Add(language, entries)` adds phrases (nested objects give keys with dots; an object of plural forms, `{one, few, many, other}`, is chosen by `count` through `Intl.PluralRules`); `Text(key, params)` returns the phrase of the language, of its base language (`pt` for `pt-BR`), of the fallback language, or the key itself, with `{name}` replaced from params; `Has(key)`; `Direction(language)` is `ltr` or `rtl`; `Key(event)` is the key of a keyboard event with `ArrowLeft` and `ArrowRight` swapped on a right-to-left element, so keys written for left to right keep their meaning; `Source(url, languages)` names dictionary files (`/locales/{language}.json`, only the languages listed when a list is given); `OnChange(callback)` / `OffChange(callback)`. Templates show phrases with `$T(key, params)`, which follows the language. `$Locales` of an Application (from its definition script) or of a Library (from its `$Root`) is a source: a path with `{language}`, or `{URL, Languages}`; an Application renders its root once the dictionaries of the language are in.
- `Elemenx.Version` — the version of this copy of the framework. `Elemenx.NoConflict()` gives the name `Elemenx` back to what had it before this copy and returns the copy. Each copy of `elemenx.js` has a namespace of its own: a second copy of the same version leaves the first in place and does nothing; a copy of another version starts, but the window keeps the first `Elemenx` (the page it serves goes on working) and the console warns; an isolated build (`elemenx build --widget`) keeps its copy to itself and the window does not see it.
- `Elemenx.Style(name, text)` — a stylesheet the framework keeps in the document and in the shadow root of every Application with `$Shadow` (the stylesheets of Components and Libraries go there too); a name keeps one stylesheet, a new text replaces it. In a shadow root `html`, `body` and `:root` of a selector are its host: `body[data-theme='dark'] .card` is `:host([data-theme='dark']) .card`.
- `$Shadow` of an Application (`true`, `'open'` or `'closed'`) renders its root in a shadow root of its mount: the styles of the page stay out of it and its styles out of the page, the links in it go through its Router, and its host takes the `lang` and `dir` of `Elemenx.Locale`.
- `Elemenx.Resource` — files embedded by a bundle (sprites, data): `Elemenx.Resource(url, text)` embeds, `Elemenx.Resource(url)` returns the embedded text or `null`, `Elemenx.Resource.Load(url, callback)` calls back `(error, text)` with the embedded text or the text fetched from the URL.
- `Elemenx.Cache(policy)` — the cache of the components; everything is off by default (`Elemenx.Cache()` returns the policy; it is `{Definitions: {MaxAge: 0, Max: 0}, Instances: {Scope: 'none', MaxAge: 0, Max: 0}}` until set; ages in milliseconds, `0` for no limit; a key not given keeps its value). `Definitions`: a definition no instance uses for `MaxAge`, or beyond the `Max` of the definitions loaded (the longest idle first), unloads the text of its template and of its style, its stylesheet and the compiled expressions of the templates; a definition of a URL loads them again for its next instance, a definition of code keeps its object and places its style again. `Instances`: an instance that leaves its place sleeps out of the page instead of being destroyed, and wakes as it was (its DOM, its state, its scroll) when its place shows it again: `Scope` `none` (the default: none sleeps), `marked` (a conditional host with `*keep`, a component with `$KeepAlive: true`), `router` (and every page of a Router, by its level, its component and the parameters of its route; a query does not count), `all` (and every conditional host such as `*if`). The items of a collection (`*for`) never sleep, and `*keep` there throws. `*keep="false"` and `$KeepAlive: false` keep an instance out of every scope. An instance asleep for `MaxAge`, beyond the `Max` asleep (the longest asleep first), or whose place goes away is destroyed. Going to sleep, a component or a directive with `$OnSleep` hears it (a component `this`, a directive `(context)`), and so do the ones inside it, and the fields of passwords and of payment cards (`autocomplete="cc-*"`) inside it are emptied; `$OnWake` follows when it comes back: timers, global listeners, media and the data that ages pause and resume there. `Elemenx.Cache.Stats()` returns `{Definitions: [{Name, Instances, Cached, Idle}], Instances: [{Name, Asleep}]}`, `Elemenx.Cache.Clear()` destroys every instance asleep and unloads every definition no instance uses, whatever the policy, and returns `Elemenx`. A wrong policy throws `Elemenx.Cache expects a policy object`, `Elemenx.Cache does not know <key>`, `Elemenx.Cache expects Instances.Scope to be none, marked, router or all` or `Elemenx.Cache expects <key> to be a number of 0 or more`.
- `Elemenx.Install` — the page as an application of the system (a PWA, which a build makes with the `PWA` of `elemenx.config.js`). The prompt of the browser to install it (`beforeinstallprompt`) is kept from the start of the page instead of showing on its own, so the Application decides when to offer it: `Available()` tells it may, `Prompt(callback)` shows it and calls back `(error, {Outcome})`, `Outcome` `accepted` or `dismissed` (an error without a prompt: the page is installed, not installable there, or not yet; a prompt shows once, the browser may give another later). `Installed()` is true in the window of the installed application and in a native program; `Manual()` on a system that installs by its own menu only (Safari of iOS: Share, Add to Home Screen). `State()` is `{Available, Installed, Manual, Waiting, Version}` (`Version` the build the page runs, once its worker answers, `Waiting` a new build waits to take its place); `OnChange(callback)` hears it change (`callback(state)`), `OffChange(callback)`; both return `Elemenx.Install`. The service worker a build names (`<meta name="elemenx-pwa-worker">`) is registered once the page has loaded. `Update(callback)` asks the server for a new build: `callback(error, {Available, Version, Current})` (an error without a worker: `Elemenx.Install has no worker: the build is not a PWA that runs offline, or the page has not loaded yet`). `Apply(callback)` updates at once, whatever is there: a new build that waits takes the place of the one before and every page of it reloads; without one the worker and its files are forgotten and the page reloads from the network; `callback(error)` only when it cannot. `PWA.Update` of the build: `auto` (a new build is taken at once, for the next start), `prompt` (it waits for `Apply`; checked at the start and every hour), `manual` (it waits for `Apply`; checked by `Update` only).
- `Elemenx.Widgets` — the Components of an Application on a page of another site, as widgets; the page loads the code once (`elemenx build --widget`: `widget.js`) and marks their places, `<div data-elemenx-widget="Cart" data-props='{"Currency": "EUR"}'></div>`. `Define(name, {Component, Application, Props, Events, Shadow})` names a widget (its Component, the name of its Application, the props it starts with, the events of the Component the page hears as DOM events of the element, bubbling with the data as `detail`, and `Shadow: false` to render in the element instead of a shadow root of it); returns `Elemenx.Widgets`. `Watch(root)` mounts every place of `root` (the document) and the ones that come later, takes away the ones removed and follows a change of their `data-props` (a place of a widget it does not define is left to another code); it returns the function that stops it. `Mount(element, name, props)` mounts one from code and returns `{Name, Element, Update(props), On(event, callback), Unmount()}`; `Unmount(element)` (`false` when nothing was there), `Names()`. The widgets of one Application share its Services; an Application of widgets needs no `$Component` (its `$Root` finds theirs). Errors: `Elemenx.Widgets does not know the widget <name>`, `Elemenx.Widgets.Mount expects (element, name, props)`, `Elemenx.Widgets.Define expects (name, {Component, Application, Props, Events, Shadow})`.
- `Elemenx.Splash` — the splash of the page, `#elemenx-splash`, which a build puts at the top of its body (the `Splash` of `elemenx.config.js`, or `splash.html` of the project): it fades and leaves the page when the first Application is ready (its `$OnReady` ran) or fails, not before its `data-min` milliseconds from the start of the page, and at the latest after its `data-timeout`. `Hold()` keeps it past the ready until `Hide()`, which takes it away (for an Application that loads its data first); `Visible()` tells whether it is still there. `Hold` and `Hide` return `Elemenx.Splash`.
- `Elemenx.Title` — document/application title facade.
- `Elemenx.RuntimeID` — runtime identifier helper.

## System namespace

Inside Elemenx definitions and runtime-owned instances, every `$*` name is reserved for Elemenx. Framework metadata uses names such as `$Template`, `$TemplateURL`, `$Style`, `$Title`, `$Component`, `$Root`, `$Mount` and `$Router`; owner APIs use `this.$Application()`, `this.$Parent()`, `this.$Service()`, `this.$Router()`, `this.$Update()` and the other `$` facades. Lifecycle hooks use `$OnCreate`, `$OnReady`, `$OnDestroy`, `$OnSleep`, `$OnWake` and related `$On*` names; `$KeepAlive` takes a component into or out of the keep-alive of `Elemenx.Cache`. Ordinary names such as `Template`, `Title`, `Application`, `Router` and `Update` are application-owned and are not legacy aliases.

## Confirmed contracts

Router reuse preserves the existing route/component instance when only Params, Query or Hash change within the same matched Route; this does not create artificial lifecycle churn. Guards still participate when navigation crosses guarded route boundaries, including browser back/forward navigation.

The Waiting component of a navigation shows first, and the route renders after the browser has painted it, so it is seen even when the route takes long to render. It stays until the route Components and the deferred Components inside them are ready (a Component whose owner shows its own `*pending` status or has `$OnChildPending` is not waited for); `NavigationEnd` follows.

The Router option `Mode` sets where the route lives (`Elemenx.Router({Mode: ...})` or `$Router: {Mode: ...}`):

- `'history'`: in the URL of the page, through the History API. The default for a page served over http.
- `'hash'`: after the `#` of the page URL, as `index.html#/orders/5?tab=2#comments`; the route of a URL without `#/` is `/`. A link to `#/path` goes to a route and a link to `#name` sets the Hash of the current route (`$Hash` is `comments` here). The `#` of the page belongs to the Router: `location.hash`, `hashchange` and CSS `:target` no longer carry the Application's own anchors.
- `'memory'`: in the entries of the browser history, which keep the URL of the page; Back and Forward and a reload keep the route, and the `#` of the page and its links stay the Application's own. A page that is not served over http (a file, the page of a browser extension, an Electron window) has no URL of its own to give the routes (a file can change no URL but its `#`, the page of an extension is `/index.html`), so `'memory'` is the default there and its first route is `/`; a page served over http starts at its path and query.

Outside `'history'` a relative link or `Go()` URL is read against the current route. Any other value throws `Elemenx.Router Mode must be history, hash or memory`.

Application-owned Services, Network resources and Workers participate in owner lifecycle cleanup. Context composition accepts the supported single-context and multi-context forms consistently across Network, Messaging and Storage.

Production bundles resolve statically bundled resources from the Bundle Registry first and retain normal Discovery as the fallback for resources not present in the bundle. This permits hybrid applications with bundled and dynamically discovered resources.

Authentication is intentionally not a Transfer/Protocol responsibility. Connection authentication belongs to connection/transport setup; application authorization remains application/server business logic.

## Tooling surface

The package exposes the `elemenx` CLI through `elemenx-cli.js`. Supported release workflows include `build`, `dev`, `serve`, and `generate` (`g`) for Application, Component, Service, Guard and Directive entities. See `docs/BUILDER.md` for build/server options and graph-aware generation.

## Release discipline

A public API addition should include a direct contract test or a stronger end-to-end test. A reproduced bug remains in the regression suite after the fix. `npm test` is the release baseline.

## Lifecycle hook naming

Lifecycle hooks are named relative to their owner. Component own readiness is `$OnReady`; `$OnSleep` and `$OnWake` of a Component or a Directive follow its sleep out of the page and its waking (`Elemenx.Cache`); Application startup uses `$OnPending`, `$OnReady` and `$OnError`. `$OnChildPending`, `$OnChildReady` and `$OnChildError` on a Component describe deferred child Component lifecycle events.

## Events

A Component that emits `change` (`$Emit('change', value)`) also dispatches the DOM event `elemenx-change` from its root element, after its own listeners: it bubbles, and its `detail` is the value, so a form or any element around the component hears every value that changes inside it. The lifecycle hooks `$OnCreate`, `$OnReady`, `$OnDestroy`, `$OnSleep` and `$OnWake` run untracked: what they read does not become a dependency of an effect of the parent that creates, destroys, puts to sleep or wakes the component (a row of a `*for`, a host of `*if` with `*keep`). The listeners of the `(events)` of a component tag and its `$Parent()` are set before its hooks run, so an event that `$OnCreate` or `$OnReady` emits reaches the owner.

`Elemenx.Events()` creates an imperative same-runtime event socket. Components, Services and Applications expose owner-aware `$Events()`. Definitions may declare `$Events: ['channel']` and receive subscribed events through one `$OnEvent(event)` dispatcher. `event.Is(name)`, `event.Is(name, handler)` provide channel matching. `event.Is(name, pipes, handler)` adds a persistent owner-bound pipeline. Pipe descriptors are evaluated in declaration order and the pipeline instance survives subsequent deliveries to the same `Is()` rule. `Elemenx.Pipe(name, factory)` registers custom Pipe types. Built-ins are `Debouncer`, `Filter` and `Gate`. Events are synchronous unless a Pipe intentionally delays delivery (for example `Gate`), and preserve JavaScript object identity; cross-context delivery belongs to Messaging.

Pipe rule identity is positional inside one Events subscription: each matching `Is()` call has its own persistent pipeline. Keep the order of piped `Is()` rules stable between deliveries. Pipeline state is destroyed with its Events socket/owner.

## Messaging

`Elemenx.Messaging()` creates a cross-context Messaging socket. Browser contexts discover their obvious Messaging neighbours automatically. An Elemenx page running inside an iframe announces itself to `window.parent`; a page opened by another window announces itself to `window.opener`. The receiving Elemenx runtime accepts same-origin announcements and creates the reverse Window bridge automatically, so normal iframe and `window.open()` relationships require no application-level `.Window()` call. Repeated registration of the same Window/origin is deduplicated. Independent same-origin tabs and windows use the built-in `BroadcastChannel` transport and announce their runtime contexts there, so normal Messaging channels can span them without explicit wiring.

Cross-origin iframe/opener relationships use the same automatic Window handshake, but are rejected by default. `Elemenx.Messaging.Origins(originOrArray)` explicitly trusts additional origins; both runtimes must trust the other origin before a cross-origin bridge is established. `HELLO` discovery may be sent with a wildcard target because it contains no application payload; accepted `WELCOME` and Messaging traffic are pinned to the verified `event.origin`. Calling `Origins()` also repeats parent/opener discovery so trust configured immediately after Elemenx loads cannot miss the initial announcement. Independent cross-origin tabs have no browser-native Window reference or shared `BroadcastChannel` and therefore are not automatically connected.

`Elemenx.Messaging.Window(target, options)` remains the explicit low-level Window transport API for non-automatic cases. It accepts a DOM selector, iframe element or browser `Window` and attaches the resolved Window through `postMessage`. `options.Origin` is both the `postMessage` target origin and the required origin for inbound messages; when omitted it defaults to the current document origin. Use `Origin: '*'` only when the peer origin is intentionally unrestricted. Inbound packets must also come from the exact attached Window. The returned handle exposes `Target()`, `Origin()` and idempotent `Destroy()`. Components, Services and Applications expose the owner-aware `$Messaging.Window(target, options)` form; its selector is resolved inside the owner's root element while the global form resolves selectors against `document`. No `$Ref` indirection is used. Owner-created bridges are destroyed with the owner. `options.Transferable: false` can disable transferable delivery for a particular Window bridge.
## WebRTC negotiation

`Elemenx.Network.WebRTC()` negotiation methods take an optional callback as their last argument: `CreateOffer(callback)`, `AcceptOffer(offer, callback)`, `AcceptAnswer(answer, callback)` and `AddICECandidate(candidate, callback)`. The callback receives `(error, result)`: the local description for `CreateOffer` and `AcceptOffer`, the accepted remote description for `AcceptAnswer`, nothing for `AddICECandidate`. It always runs after the method has returned. An exception thrown by the callback is reported as an uncaught error, not swallowed.

The methods return the WebRTC object, like its other methods, and never a Promise. Without a callback, a failed negotiation step is reported as a `Transport.Error` event whose data holds `Error`, `Operation` (the method name) and `Connection`.

## Transfer Encoder

`Elemenx.Network.Transfer({Encoder: ...})` encodes every chunk (or the whole payload) before it is sent. A synchronous Encoder is `function (value, context)` and returns the encoded value. An asynchronous Encoder declares a third parameter, `function (value, context, done)`, and calls `done(error, value)` once. An Encoder that throws, or calls `done` with an error, fails the transfer with a `Transfer.Error` event. Returning a Promise is not supported: it fails the transfer with an explicit error.

## Guard waiting

A guard that needs time returns `this.$Wait(function (done) { ... })` and calls `done(result)` later, with the same results a synchronous guard returns. `$Wait` also accepts a ready value. A Promise is refused: the navigation is denied and `GuardFailed` receives a failure whose `Reason` is `'InvalidWait'` and whose `Data` is the error.

## Redirects and navigation errors

A guard or an `$OnRouteLeave` hook that returns a path redirects the navigation there. The redirect does not ask the leave hooks of the current routes again: they already agreed to leave. A path no route matches, shown by the `NotFound` component, asks the leave hooks too: a refusal keeps the page, a path redirects.

A navigation whose target cannot be loaded or rendered (a missing route, Waiting, GuardFailed or NotFound component, a missing guard or outlet) ends with the Router event `NavigationError`. Its data is the navigation context with `$Error` set to the error; the URL returns to the committed route, and `Go()` / `Replace()` never throw for it. Without a `NavigationError` listener the error is reported as an uncaught error.

## Deferred component failures

A Component whose template or style cannot be loaded renders the `*error` status of its declaration and calls `$OnChildError` of its owner (an Application root reports to the Application `$OnError`). The error is logged to the console only when no such hook received it.

## Exceptions in listeners and callbacks

Elemenx calls event listeners the way the DOM does. An exception thrown by a listener (`On(...)` of Events, Messaging, Network objects, Storage operations, workers, `$On` of Components, Router events) is reported as an uncaught error during the dispatch, before the next listener runs: it reaches `window.onerror` and `error` listeners with its original stack, and the console unless a listener calls `preventDefault()`. The remaining listeners still receive the event, and the code that dispatched it is not interrupted. The same applies to callbacks Elemenx calls from asynchronous browser operations, such as WebRTC negotiation callbacks.
