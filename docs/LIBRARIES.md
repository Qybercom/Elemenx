# Elemenx Libraries

A Library is a first-class Elemenx extension graph. It can provide Components, Services, Guards, Directives and Traits (`Elemenx.Trait`, in `traits/`: the props, methods and hooks Components take with `$Traits`) through the same Discovery and production Bundle mechanisms used by an Application. A Trait is loaded the first time a Component that takes it is used; a build carries every Trait of a Library, and the base a Component names in `$Extends`.

External libraries are registered before the Application that uses them:

```js
Elemenx.Library('Mosaic', {
	$Root: 'libraries/Mosaic'
});

Elemenx.Application('Application', {
	$Use: ['Mosaic'],
	$Component: 'Root',
	$Root: 'application'
});
```

`$Use` accepts a library name or an Array. The Application exposes the resolved declaration through `$Libraries()`.

In development, Elemenx builds a Discovery graph for every used Library. Component resolution falls back to those graphs when an entity is not present in the Application graph. Library Services and Directives are loaded before the Application root starts. CSS files listed by the Library `index.js` are attached once per Library. Unknown names in `$Use` are skipped with a warning and do not block Application startup; errors while loading an existing Library remain fatal for that startup.

In production, Builder scans Library roots declared in the entry file. Non-Component entities remain available to the Application, while Components are included by reachability from bundled Application templates and then transitively from selected Library Component templates. Unused Library Components are omitted. External templates/styles owned by selected Components are inlined by the normal Bundle pass, while CSS assets declared by the Library graph are copied to their Library path in `dist`. The runtime therefore does not require Library Discovery source graphs to start bundled entities.

Packs. A Library may name in `packs.json`, in its root, the large files that few pages need: `{"brands": {"Files": ["icons/brands.svg"], "Uses": ["brands:"]}}`. `Files` are paths from the root (files of the `index.js` graph), `Uses` the texts that show an Application needs them, `Language` makes a pack of one language, `Bundled` keeps it in the standalone bundle of `npm run dist` (a build of an Application still takes it only when it is used). A pack changes nothing at run time, its files load as any other; the tools use it: a build takes a pack only when the Application uses it (or `--packs` asks for it), `elemenx build --single` embedding it, a build in a folder copying its files, and the standalone bundles of `npm run dist` carry a pack in a script of its own (see `docs/BUILDER.md`). ElemenxUI has the packs `emoji`, `emoji.ru`, `cities`, `cities.ru`, `brands`, `files`, and the themes `contrast`, `darcula`, `soft` (bundled), `fantasy`, `scifi` and `glassy` (a pack of a stylesheet: a build carries a theme only when the Application names it, as `Theme.Use('darcula')` or `data-theme="darcula"` does, or lists them all, `Theme.Themes()`, and a site build links only those from its page).

The built-in standard library is named `ElemenxUI` and lives at `libraries/ElemenxUI`. It is available without an explicit `Elemenx.Library(...)` declaration; an Application only needs `$Use: ['ElemenxUI']`. The development server exposes package libraries through `/libraries/`, so examples and installed-package consumers use the same canonical source instead of carrying private copies. The executable catalogue is the Advanced example route `/ui`.

## ElemenxUI

### Phrases

Every phrase ElemenxUI shows (labels, placeholders, the names of buttons for screen readers, messages) is a key of `Elemenx.Locale` under `ui.` (`ui.common.clear`, `ui.emojiPicker.searchLabel`) with its English and Russian dictionaries in `locales/en.json` and `locales/ru.json`; `Elemenx.Locale.Language('ru')` switches them, and a page in another language shows the English ones until its dictionary is there. A text prop of a component (`Placeholder`, `Empty`, `CloseLabel`...) is empty by default: the phrase of the language shows, and a value of the owner takes its place. Another language is a `locales/<language>.json` with the same keys (the test `tests/regression/locales.test.js` checks them) and its code in the `Languages` of the declaration of ElemenxUI; an Application may also add or change phrases with `Elemenx.Locale.Add('de', {ui: {common: {clear: 'Leeren'}}})`.

The dates, numbers, countries and currencies of the components follow the language of `Elemenx.Locale` too (their `Locale` prop takes its place). A right-to-left language (`ar`, `he`, `fa`...) sets `dir="rtl"` on the page and ElemenxUI mirrors: its stylesheets use logical properties (`margin-inline-start`, `inset-inline-end`, `text-align: start`), the arrows to the left and to the right keep their meaning (`Elemenx.Locale.Key`: the next tab, day or item is toward the end of the line), sliders run from right to left, a popup opens at the start of its anchor (its right edge) and a side menu to the left, and the icons of a direction (`chevron-left`, `arrow-right`, `page-first`, `undo`, `reply`...) point the other way. Charts and the fields of Latin formats (an email, an address, a code: `Preset` with `Direction: 'ltr'`) stay from left to right.

### Styles

The Library `index.js` attaches one stylesheet, `index.css`, to every Application that uses ElemenxUI. It holds the foundation (fonts, `html`/`body`, the theme colors, scrollbars, headings, the layout primitives `elemenx-screen`, `elemenx-container` and `elemenx-column` with their modifiers `fill`, `centered`, `wrappable`, `block`...) and everything shared by several Components: typography (`elemenx-title`, `elemenx-text`, `elemenx-label`, `elemenx-caption`, `elemenx-footnote`, `elemenx-link`, `elemenx-code`, `elemenx-kbd`), lists (`elemenx-ul`, `elemenx-ol`, `elemenx-ol outline`, `elemenx-ul check`, `elemenx-list divided`), blocks (`elemenx-panel`, `elemenx-card`, `elemenx-block`, `elemenx-section`, `elemenx-callout`, `elemenx-badge`, `elemenx-divider`, `elemenx-spacer`), tables (`elemenx-table` with `compact`, `striped`, `bordered`, `sticky`), the field and choice controls, floating panels, loaders and drag and drop. Every other Component carries its own stylesheet, which the production Bundle includes only when the Component is used.

The theme policy is the `data-theme` attribute of `body`: `system` (or no attribute) follows the operating system through `prefers-color-scheme`, `light` and `dark` force a theme. `index.css` applies the policy before any script runs; `data-scheme` holds the scheme shown. Every color, corner, control height, type size and duration is a `--elemenx-*` token of the theme, so a Component never names one directly. A custom theme is one plain CSS file that changes the tokens and, by their classes, the rules of any Component: see `docs/THEMING.md` and the list of classes in `docs/THEMING-CLASSES.md`. Sizes follow the 8-4-2-1 grid: controls are `small` (24px), `medium` (32px, the default), `large` (40px) and `giant` (56px); the base font is 14/20px. `Shape="round"` (the class `round`) rounds a button or a field.

### Icons

`index.svg` is the sprite of the semantic icons: `<Icon Name="save" />`, with `Size` (16 by default) and `Label` for an icon that carries meaning on its own. It includes alignment (`align-*`), position (`position-*`), fit (`fit-*`) and sort direction icons, media and call icons with their switched off pairs (`mic`/`mic-off`, `video`, `camera`, `volume`, `speaker`, `headphones`, `screen-share`, `call-end`, `record`, `hand`; `backspace`, the key that erases), faces (`smile`, `laugh`, `wink`, `neutral`, `sad`, `reaction`, `sticker`) and social actions (`like`, `dislike`, `heart`, `star` and `bookmark`, each with its `-filled` pair; `repost`, `quote`, `reply`, `reply-all`, `forward`, `comment`, `share`, `mention`, `hashtag`, `follow`, `unfollow`, `following`, `report`, `verified`, `trending`, `fire`, `gift`). The file format icons are the set `files` (`files:js`, `files:pdf`...: a sheet with a colored badge); `<FileIcon Name="report.pdf" />` picks the icon of a file name (`Icons.File(name)`: about 170 formats, their other extensions, `.tar.gz`, `Dockerfile`, `Makefile`, `.gitignore`...). The catalogue lists every name. The first `Icon` copies the symbols of the sprite into a hidden `<svg id="elemenx-icons">` of the page (as `elemenx-icon-<name>`), and every icon then draws the shapes of its symbol itself, with no `<use>` (the `*glyph` directive): Chrome rebuilds the shadow tree of every `<use>` when the page restyles, and with the developer tools open the icons stay blank until a theme change is over. `data-icon` on the `<svg>` names the icon. An `Icon` with its own `Sprite` draws that file with `<use>`.

Icon sets. A name with a set before it draws a symbol of another sprite: `<Icon Name="weather:rain" />`. The Library brings four sets in `icons/`, loaded only when an icon of theirs first shows: `files` (file formats), `brands` (349 logos of social networks, messengers, developer tools, programming languages, frameworks and libraries, databases, platforms and AI services, cloud services, payments and stores from Simple Icons, CC0, named by their Simple Icons slug: `brands:github`, `brands:telegram`; `Colored="true"` paints a logo in the color of its brand; the logos are trademarks of their owners), `music` (instruments, notation, studio and player icons) and `weather` (sky, precipitation, wind, temperature, sunrise and sunset, the phases of the moon); and six themed line sets of about fifty icons, packs loaded only when an icon of theirs first shows: `sport` (balls, rackets, gear, the gym, winter and water sports, trophies: `sport:soccer-ball`), `racing` (flags, the track, cars and bikes, the cockpit, gauges, the engine, the pit: `racing:checkered-flag`), `science` (matter, the laboratory, measures and mathematics, light and space, life, machines: `science:atom`), `art` (paint, drawing and writing, pictures, digital tools, crafts, the stage: `art:palette`), `cinema` (film, cameras and the set, the theater, fame, playback: `cinema:clapperboard`) and `games` (devices, board and table games, pixels, the hero, arms, treasure and the world: `games:gamepad`). The parts of a weather icon carry classes (`sun`, `moon`, `cloud`, `rain`, `snow`, `bolt`, `wind`, `fog`, `thermometer`): `Colored="true"` paints them with the `--elemenx-weather-*` colors of the theme. The `Icons` Service adds the sets of the Application; `elemenx icons` (see `docs/BUILDER.md`) builds a set from a directory of SVG files. A symbol keeps its own `fill` and `stroke` attributes, so a filled or a colored set draws as it is made.

### Services

- `Theme`: `Policy()` returns the policy, `Policy('dark')` sets it, `Next()` cycles it, `Resolved()` returns the scheme shown. Named themes (the Library brings `contrast`, `darcula`, `soft`, `glassy` (light and calm as the desktops and phones of today: the font of the system, round corners, a blue accent, green switches, and the floating parts of frosted glass), and for games `fantasy` and `scifi`): `Register(name, {URL, Label, Schemes})`, `Use(name, callback)` (loads the stylesheet of the theme when it has one, then shows it; `Use('default')` goes back to `index.css`), `Scope(element, name, callback)` (one part of the page in a theme or a policy of its own: `data-theme` and `data-scheme` on that element; `null` gives it back to the page), `Theme()`, `Themes()`; the Library brings `contrast`, `darcula` and `soft`. `OnChange(callback)`/`OffChange(callback)` report `{Policy, Theme, Name}`, including system changes under `system`. The policy and the theme are remembered in `localStorage` (`Persist`, `StorageKey`); the first policy comes from storage, then from the page's `data-theme`, then from `Default` (`system`). See `docs/THEMING.md`.
- `Icons`: the icon sets. `Register(name, source)` adds a set from a sprite URL (relative to the page; same origin or CORS) or from the markup of a sprite (`'<svg>...</svg>'`); a set registered again replaces the old one, `Forget(name)` removes it. `Load(name, callback)` loads a set now and calls back `(error, names)`; otherwise a set loads when an icon first needs it. `Override('save', 'brand:disk')` makes every icon named `save` draw another symbol (`Override('save')` restores it), so an Application can restyle the icons of every Component. `Names(set)`, `Sets()`, `Ready(set)`, `Href(name)`; `OnChange(callback)`/`OffChange(callback)` report `{Set}` when a set loads and `{Override}` when an override changes. The sets are shared by every Application of the page.
- `Emoji`: the emoji data, loaded when first needed: `data/emoji.json` (the groups and the English names of `emoji-test.txt` of Unicode, Emoji 18.0) and the names and keywords of CLDR 48 in English and in the language of the page (`data/emoji-en.json`, `data/emoji-ru.json`; `Locales`, `Locale`). `tools/emoji.js` builds them from the official files: `node tools/emoji.js emoji-test.txt <cldr-annotations-full> <cldr-annotations-derived-full> libraries/ElemenxUI/data en,ru`. `Load(callback)` calls back `(error, groups)`; `Groups()`, `Find(char)`, `Search(text, limit)` (every word of the text starts a word of a name or a keyword; the name itself first), `Name(emoji)` (in the language of the page), `LoadLanguage(locale, callback)` to search in one more language, `Keywords(locale, map)` to add keywords, `Tone(value)` and `Toned(char, tone)` for skin tones, `Recent()` and `Used(char)` (both remembered), `Supported(char)`. `Single(text)` returns the emoji a text is made of when it is one emoji and nothing else, or an empty text.
- `Cities`: the cities of the world from GeoNames (every city of a thousand people or more, about 171 000; CC BY 4.0, so an Application shows `Attribution`, `Cities: GeoNames (geonames.org), CC BY 4.0`, where the cities are seen), loaded when first needed: `data/cities.txt` (the names, countries, region codes, coordinates and time zones, sorted by name), `data/regions.txt` and the names in the language of the page (`data/cities-ru.txt`; `Locales`, `Locale`). `tools/cities.js` builds them from the GeoNames files: `node tools/cities.js cities1000.txt admin1CodesASCII.txt alternateNamesV2.txt libraries/ElemenxUI/data ru`. A city is `{ID, Name, Country, Region, Latitude, Longitude, TimeZone}` (`Name` and `Region` in the language of the page, `Country` an ISO 3166 code, `TimeZone` an IANA zone). `Load(callback)` calls back `(error, count)`; `Search(text, options, callback)` calls back `(error, cities)`: the names that start with the text first, then the names with a word that does, each by name (not by population), without case and diacritics and across alphabets (`moskva` finds `Москва`); `options` `Country`, `Limit` (20). `Find(id, callback)`, `Nearest(latitude, longitude, options, callback)` (`options.Country`), `Clock(city or time zone, date)` (`{Date, Time, Offset, TimeZone}` there, now by default), `Label(city)` (`Name, Region, Country`) and `Place(city)` (`Region, Country`), in the language of the page.
- `Badges`: the badges over the corner of an element. `Describe(value)` reads a value (a count: 0 shows none, more than `Max` (99) shows 99+; `'dot'`; `'busy'`; a text; or `{Value, Tone, Max, Label}`) into `{Shown, Kind, Tone, Text, Label}`, `Classes(value)` the classes of its badge; `*badge` and the `Badge` of a `Button` use it.
- `Forms`: the models of forms, as Angular has them, kept in the state of a Component so it renders as they change. `Control(value, validators)` (a list of validators, or `{Validators, Async, Disabled}`: an async validator calls back its errors later, the control pending meanwhile), `Group({name: node}, validators)` and `Array([node], validators)` (`Push`, `Insert`, `RemoveAt`, `Clear`). - `Panels`: the panels a component declares in its template, as the tabs of `Tabs` (`Tab`) and of `Ribbon` (`RibbonTab`): `Read(root, selector, owner)` (the panels of root, not those of a nested owner), `Data(panel)` (its `data-*` attributes as `{Name: text}`, in PascalCase), `Watch(root, selector, callback)` (calls back, once a frame at most, as panels come, go or change; returns the function that stops it).

- `Find`: text found in the DOM, for the find bars of `RichEditor` and `Terminal`: `Ranges(root, query, {Case, Word, RegExp})` (the matches as DOM Ranges, across elements), `Show(owner, ranges, index)` (marks them with the highlights of the browser, `::highlight(elemenx-find)` and `::highlight(elemenx-find-current)`, nothing added to the text, and brings the current one into view), `Clear(owner)`.
- `Formulas`: `MathML(text, display)`, a formula written as in LaTeX as the MathML the browser draws: numbers, letters, the words of functions, operators and relations, Greek letters, groups, powers and indices, `\frac`, `\sqrt` (with `[n]`), sums, products and integrals with their limits, `\lim`, `\left`/`\right`, accents (`\hat`, `\vec`, `\bar`...), `\text`, `\mathbf`, `\mathbb`, spaces and the matrices (`matrix`, `pmatrix`, `bmatrix`, `vmatrix`, `cases`); a text it cannot read comes back in an `<merror>`.
- `Stickers`: `Register({ID, Title, Icon, Items: [{ID, URL, Title, Keywords, Emoji}]})` adds a pack (any image the browser draws, animated ones too), `Forget(id)`, `Packs()`, `Find('pack/id')`, `Search(text)`, `Recent()`/`Used(sticker)`, `Favorites()`/`Favorite(sticker)`/`IsFavorite(sticker)` (remembered), `OnChange`/`OffChange`. `Emoji` are the emoji a sticker means (a text or a list): `ByEmoji(char, limit)` lists the stickers of an emoji (starred and recent ones first; skin tones do not count) and `Search` finds them by emoji too.
- `Format`: the formats of the cards in the language of the page (`Locale`): `Count(12400)` (12K), `Date(value, style)`, `Day(value)` (`{Day, Month}` of a date badge), `Relative(value)` ('5 minutes ago'), `Money(amount, code)`.

An error names its `Line` and `Column`.
- `Countries`: `List(locale)` returns every country with `Code`, localized `Name`, dialling code `Dial`, national number `Mask` and `Currency`, sorted by code; `Find(code)`, `Match(digits, preferred)`.

- `Hotkeys`: keyboard shortcuts. `Bind(keys, callback, {Scope, Inputs, Prevent, Description, Group})` returns an ID for `Unbind(id)`; keys like `Mod+K` (Ctrl, or Command on macOS), `Ctrl+Shift+P`, `Escape` or a sequence `g i`. - `Biometric`: the fingerprint, face or PIN of the device through WebAuthn (HTTPS or localhost; not an IP address). `Available(callback)`, `Register(options, callback)` and `Verify(options, callback)` for a server that keeps the credentials and checks the signatures (the results are base64url, ready to send), `Check(callback)` for a local check without a server (a convenience, not a security measure), and `Guard(options)`, a guard for `Reveal.Guard`.
- `Clipboard`: `Copy(text, callback, {Toast})` (with a fallback where the Clipboard API is missing) and `Read(callback)`.
- `Platform`: the platform the Application runs on (its windows, its icon, the taskbar, the tray, the dialogs, the notifications), one API wherever it runs: in a program of `elemenx build --native desktop` through the bridge of the program, in a browser with what the web can (a file picker, a download, `confirm`, a new tab, the full screen);   ```js

  	var data = event.data ? event.data.json() : {};

  	event.waitUntil(self.registration.showNotification(data.Title || '', {body: data.Text, icon: data.Icon, tag: data.Tag, data: {URL: data.URL}}).then(function () {
  		return self.clients.matchAll({type: 'window'});
  	}).then(function (clients) {
  		clients.forEach(function (client) {
  			client.postMessage({Elemenx: 'push', Type: 'push', Data: data});
  		});
  	}));
  });

  self.addEventListener('notificationclick', function (event) {
  	event.notification.close();

  	if (event.notification.data && event.notification.data.URL)
  		event.waitUntil(self.clients.openWindow(event.notification.data.URL));
  });

- `Print`: printing of a part of the page, with no button of its own: `Element(target, {Title, Theme, Class, Style, Margin, Language}, callback)` prints a DOM node (a copy) or a text of HTML in a frame with the stylesheets of the page (and of its shadow root), in the light theme unless `Theme` names another (`false`: the theme of the page); a PDF comes from the dialog of the browser. `Document(target, options)` returns the HTML of that frame. `CodeEditor` prints through it.
- `RichText`: the document of `RichEditor`. `Sanitize(html)` keeps the schema (paragraphs, headings `h1`-`h4`, quotes, preformatted code, lists, rules, tables, images and links; `strong`, `em`, `u`, `s`, `code` and line breaks inside): other tags give their text (`b` becomes `strong`, `i` `em`), scripts, styles, frames and forms go with their content, and only safe attributes stay (`href` of http, https, mailto, tel or a relative URL; `src` also of a `data:` picture; `alt`, `title`, `colspan`, `rowspan`, `start`). The HTML is read in an inert template. `ToMarkdown(html)` and `FromMarkdown(text)` (CommonMark with the tables, strike and fenced code of GitHub; underline stays `<u>`), `Text(html)`, `SafeURL(url, image)`.
- `Gamepad`: gamepads (the Gamepad API, standard mapping) work the page the way the keyboard does, so every component that follows the keys follows a pad. The d-pad and the left stick send the arrow keys to the focused element and, when no component takes them, move the focus to the nearest control on that side (`Move(direction, scope)`, inside the open dialog; a held direction repeats); A sends Enter and X Space, and either presses the focused control when no component took the key (a button, a check box, an option; A follows a link too); B sends Escape, and cancels the open dialog when no component took it (an open popup closes first); Y sends Delete. The Service starts with ElemenxUI, so a pad works on every page. A pad that the system reports twice (XInput and HID, Steam) presses once; the stick goes the way it leans most; a pad without the standard mapping only moves (its buttons are the events `b0`, `b1`...); the pad drives the page while it is shown and has the focus, and one Elemenx drives it when several Applications or widgets use pads (`window.ElemenxGamepad`). `On(name, callback)` / `Off(callback)`: `button` (`{Button, Pad}`: `a`, `b`, `x`, `y`, `lb`, `rb`, `lt`, `rt`, `select`, `start`, `ls`, `rs`, `up`, `down`, `left`, `right`, `home`), `connect`, `disconnect`, `change` (another kind of pad). `Pads()`, `Kind()` (`xbox`, `playstation`, `nintendo`, `generic`, or empty without a pad), `Label(button, kind)` (A, ✕, B...), `Navigate` (false keeps only the events). A browser reports a pad once one of its buttons is pressed on the page.
- `PictureInPicture`: a video or any part of the page in a small window of its own over the other windows of the system. `Supported(kind)` (`video`, or `document` for any element: Chrome and Edge), `Video(video, callback)` (in, or back when it is there), `Document(element, {Width, Height, Title}, callback)` (the element moves into the window with the styles, the theme and the direction of the page, a frame with a button back takes its place, and it comes back when the window closes), `Close(callback)`, `Active()` (`{Kind, Element}` or null), `OnChange(callback)` / `OffChange(callback)`. A window opens only after a press or a key of the user.
- `Windows`: the order of the `Window` components of the page. `Front(window)` puts one over the others and makes it the active one, `Active()`, `List()` (from the back to the front), `Place()` (the next place of the cascade of new windows), `OnChange(callback)` / `OffChange(callback)`; `Load(key)` and `Save(key, geometry)` keep the windows with `Persist` in localStorage.

- `GameItems`: the rules of moving the items of a game. `Move(item, current)` returns `{To, From}`: what a place holds after `item` comes onto it (`current` is what it held) and what goes back to where the item came from; piles of the same `ID` join up to `Stack`, other items swap. `Stacks(a, b)`, `Take(item, count)` (an item used up: `null` when none is left), `Place(element)` (where the card of an item shows beside an element) and `Carded(item)` (whether an item has more to show than its name). `GameInventory` moves inside its grid with it, and the owner of the other places of a game does the same with what their drop events carry.

### Traits

- `Declared`: a Component that reads what is declared inside it (`Pipeline` its `PipelineStage`, `Mosaic` its `MosaicItem`, `Quiz` its `QuizQuestion`, `BusinessCalculator` its `CalculatorField` and `CalculatorResult`): child Components that show nothing themselves, a hidden element of each with its props in `data-item`, inside the element its `DeclaredSources` (a selector) names. It reads them once it is ready and again whenever they change (their elements, their `data-item` and, with `DeclaredText`, their texts), through the `Declarations(sources)` of the Component (by default the `data-item` of each), and gives what changed to its `Declared(declared)` (by default kept in `Own().Declared`, `Version` counted up for the template); `ReadDeclared()` reads them at once.

### Directives

- `*popup` places a floating panel in the top layer (a popover of the browser, so no overflow, transform or stacking of the parts of the page around it cuts or hides it; a fixed panel in a browser without popovers) next to its anchor (`data-placement` bottom-start, bottom-end, top-start or right-start, turning to the other side when there is no room) and dismisses it on an outside press or Escape; it follows its anchor while the page scrolls and its own size while its content changes.
- `*modal` opens a `<dialog>` as a modal.
- `*mask` keeps an input inside a mask (`#` digit, `A` letter, `*` both) whatever way the text arrives; `Guide` shows the whole template, `Backspace: 'skip'` moves over separators.
- `*resizable` adds resize handles (`right`, `left`, `bottom`, `top`, `corner`) with limits and keyboard support.
- `*draggable` and `*droppable` drag items by pointer onto targets that accept their `Type` (`Hold`: on a touch screen a finger scrolls the page and a press held still that many milliseconds takes the item); a target can also take files and text dragged from outside the browser. A target with `Sort` (`vertical`, `horizontal` or `grid`) is an ordered list: a line marks the place of the item and `Index` in the `dropmove` and `dropped` events tells it, so items can be reordered within a list and between lists. `OffsetX` and `OffsetY` in the detail are the point of the item that the pointer holds. A drag selects no text and survives a new rendering of its element.
- `*hotkey="'Mod+S'"` clicks the element on its keys (Hotkeys Service) and sets `aria-keyshortcuts`; `Scope: 'local'` limits it to the closest section, dialog or form.
- `*copy="text"` copies text on a click (Clipboard Service), with `copied` and `data-copied` for a moment and an optional toast.
- `*badge="value"` puts a badge over the corner of any element (an item of a toolbar, of a list, a picture): a count (`danger` by default; more than 99 is 99+; 0 shows none), `'dot'` (something new), `'busy'` (a ring that turns while a task runs), a text, or `{Value, Tone, Max, Label}` with `Tone` accent, info, success, warning or danger and `Label` what a screen reader says of it. A `Button` takes one by its `Badge`.
- `*swipe` makes an element follow a finger along an axis (`*swipe`, `*swipe="'y'"` or `{Axis, Threshold, Mouse}`; the page still scrolls along the other one) and dispatches `swipemove` (`{DX, DY}`) while it moves, then `swipe` (`{Direction, DX, DY}`: left, right, up or down) past `Threshold` pixels or on a flick, or `swipecancel`; a move that begins on a field, a slider or `[data-no-swipe]` is left to it. `Gallery` and the pictures of a `ProductCard` swipe by it, and a menu sheet closes by a swipe down on its top.
- `*itemcard="item"` shows the card of an item of a game on any element, under the pointer or the focus (the reward of a quest, an item of your own place): its name in the color of its rarity, its type, stats and description, beside the element (`GameItems.Place`), in the top layer (a popover: no scrolling box, transform or filter cuts it) and in the theme of its part of the page; an item with only a name shows none. GameInventory and GameSlot show the same card.
- `*layer` puts its element in the top layer of the page while it is in the page (`*layer="Open"`: while the expression is truthy): a part fixed to the viewport (a host of toasts, a tour, a window of the page, the point a menu opens at) is placed by the viewport wherever it is, even inside a box with containment (`content-visibility`, `contain`), a transform or a filter. It keeps its place, size and look and stays where it is in the DOM (its theme, its events); a new truthy value brings it on top again (`*layer="Z"`: windows in the order of their stack). The hosts of toasts, notifications and achievements, Tour, Consent, the windows of `Bounds="viewport"`, the points of ContextMenu and of the menu of a chat message, the sheet of MenuList, the panel of a shrunk RibbonGroup, RibbonBackstage and the card of GameSlot and GameInventory use it.
- `*blur` makes an element a surface of frosted glass, what is behind it blurred (`backdrop-filter`) and seen through the tint of the surface: `*blur` alone takes the tokens of the theme (`--elemenx-blur-*`), `*blur="12"` blurs 12 pixels, `*blur="{Radius, Saturate, Tint}"` sets each (`Saturate` 1 keeps the colors, `Tint` 0 clear glass, 1 the surface); where the browser cannot blur, or the reader asks for less transparency (`prefers-reduced-transparency`), the surface is solid. The class is `elemenx-blur`.
- `*tip` shows a tip of the theme over an element, as the ScreenTips of Microsoft Office: `*tip="'Save'"` or `{Title, Text, Placement, Delay, Class, Element, Render, Disabled}`, the `Title` in bold with the `Text` under it; it shows after `Delay` (500 ms) under the pointer or at once on a focus from the keyboard, one at a time (role tooltip, `aria-describedby`). The items of a `RibbonGallery` and the kinds of a `DesignerPalette` show their names and descriptions by it.
- `*glyph` draws a sprite symbol inside an `<svg>` (used by `Icon`).
- `*mount` puts custom content into an element: a DOM node, or an object with `Render(container, item)`.
