PlanetData: планета как данные (docs/PLANET-FORMAT.md) — паспорт и слои, каждый тайлами на гранях куба: у каждой грани своё дерево квадрантов, уровень 0 — вся грань, уровень L — 2^L на 2^L тайлов. ScenePlanet читает их вместо своего шума: ScenePlanet.UseData(key, data), а затем Make({Data: key}).

- Bake(options, settings, callback(error, data)) — записать планету с опциями ScenePlanet как данные, в воркерах планеты. settings: ID, Name, Depth (самый глубокий уровень высот, 3), Size (отсчётов на сторону тайла, 129), Biomes (самый глубокий уровень биомов, 2), Climate и Plates (самые глубокие уровни климата и плит, как у биомов), Vectors (true — ещё и её реки, поселения и трассы, как их делает Scene: из высот VectorSize, 256, на сторону грани, и Towns, 20000, перебранных мест), Progress(done, total). Высота тайла уровня — рельеф планеты не мельче его текселя.
- Open(source, callback(error, data), settings) — данные планеты: то, что дал Bake; байты её файла (Save; Blob, File, ArrayBuffer или Uint8Array); URL файла (.planet, .zip, blob:) или папки её файлов (planet.json и тайлы, которые он перечисляет). Все тайлы прочитаны до вызова callback. Планета из сети, прочитанная один раз, хранится в браузере (Store), и та же планета снова (тот же manifest) берётся оттуда: из сети приходит только planet.json. С settings.Levels у планеты из сети сразу читаются тайлы до этого уровня (её файл — диапазонами байтов: каталог в конце, паспорт, грубые тайлы одним диапазоном; папка — по файлам), а более мелкие — по мере надобности: Need(data, direction, reach, finest, callback(error, names)) читает тайлы вокруг направления на reach км, не мельче finest км; ScenePlanet.AddTiles отдаёт их воркерам. Scene делает это сама при Levels в Surface-Planet.
- Save(data) — байты её файла: zip из planet.json, векторов и тайлов (Archive.Zip), грубые тайлы первыми; Pack(data, callback(error, bytes)) — тот же zip, сжатый (Archive.Compress). Open читает оба.
- Prune(data, tolerance) — адаптивная глубина: тайлы, которые не говорят больше, чем более грубый тайл, прочитанный в том же месте (с точностью tolerance: {Height: метры, Climate, Plate, Biome: шаги байта}), убираются; читатель тогда читает грубый. Bake делает это сам (settings.Tolerance, по умолчанию {Height: 2, Climate: 1, Plate: 0, Biome: 0}; false — оставить всё). Возвращает, сколько убрано.
- Store(data, callback(error)), Stored(id, callback(error, data)), List(callback(error, [manifest])), Remove(id, callback(error)) — планеты в браузере (IndexedDB, база elemenx-planets), чтобы открыть их снова без файла; хранятся, пока их не удалят. Stored без такой планеты (или без IndexedDB) даёт null, Store без IndexedDB — ошибку.
- Tile(bytes) и Bytes(layer, face, level, x, y, values, type) — тайл из байтов его файла ({Face, Level, X, Y, Size, Values}) и обратно; type — тип слоя (rgba8 — четыре байта на отсчёт), без него — по массиву (int16 или uint8). В файле отсчёт хранится разностью с предыдущим в строке (первый в строке — с первым строки выше): так рельеф лучше сжимается.

data — {Manifest, Tiles: {имя: Int16Array или Uint8Array}, Vectors: {Rivers, Settlements, Highways}}. Manifest — паспорт: Format (elemenx-planet), Version (1), ID, Name, Radius (км), Sea, Seed, Origin ({Kind: generated, Options} — из чего она сделана), Size, Layers ({Height: {Type: int16, Unit: m, Depth}, Edit (изменения рельефа в метрах, плюс или минус, только там, где они есть; после Bake тайлов нет), Biome: {Type: uint8, Depth, Table — имена биомов, 0 — море}, Climate: {Type: rgba8, Depth} — тепло (-40…50 °C), влажность, ветер на восток и на север (-16…16 м/с), Plate: {Type: rgba8, Depth} — плита, 255 у океанической, км до соседней плиты десятками, как они сходятся (Push, -2…2)}), Vectors (пути её векторов в файле: vectors/rivers.json, vectors/settlements.json, vectors/highways.json), Tiles (имена всех тайлов). Имя тайла — слой/грань/уровень/x-y, в файле — tiles/имя.bin: заголовок в 32 байта (EPT1, тип отсчётов, грань, уровень, фильтр, x, y, размер) и отсчёты строка за строкой. Первый и последний отсчёты тайла лежат на его краях, так что два соседних тайла делят отсчёты края и чтение между ними не даёт шва; отсчёты стоят на грани по равным углам.

Планета данных в ScenePlanet: не мельче самого мелкого тайла в точке её высота — из тайла (между четырьмя отсчётами), это дешевле рельефа. Мельче у планеты, сделанной из опций (Origin generated), — рельеф этих опций и поверх него Edit, так что планета, сделанная Bake, и планета её опций — одна и та же (рельеф не гладок внутри текселя: чтение между отсчётами теряло километры хребтов). У планеты из одних данных — её тайл, поверх её реки и запечённые локации. Биом — из ближайшего отсчёта его тайла. Климат (тепло, влажность, ветер) не мельче тайла — из тайлов Climate, мельче у планеты из опций — из её опций; плиты планеты из одних данных — из тайлов Plate. Её реки, поселения и трассы — её векторы, если в опциях не даны свои: Scene не делает их заново.

Правки и объекты. Правки (кисти PlanetEditor: поднять, опустить, выровнять, сгладить) и запечённые локации — в edits.json, отдельно от опций генерации; Retile(data, edits, callback(error, names)) пересобирает только задетые правками тайлы. Документы локаций (то, что SceneEditor расставил на них) — объекты планеты: Objects(data, id, callback(error, document)) читает документ по запросу, SetObjects(data, id, document) меняет его (null — убрать).

Части и хранилища (docs/SPACE-FORMAT.md). Читается и пишется часть, заданная описанием, а не путём: {Kind: 'manifest'}, {Kind: 'tile', Layer, Face, Level, X, Y}, {Kind: 'vector', Name}, {Kind: 'edits'}, {Kind: 'objects', ID}. Хранилище — {Read(part, callback(error, bytes или null)), Write(part, bytes, callback(error))} и по желанию ReadMany, WriteMany, Remove, Watch(callback(part)) (часть изменилась в другом месте). Open(store, callback, {Levels}) открывает планету из хранилища (мелкие тайлы — через Need, объекты — по запросу), Write(data, store, callback, whole) пишет только изменённое с прошлого чтения или записи (whole — всё). Browser(name) — хранилище в браузере (IndexedDB, ключ на часть). Remote({Transport}) — хранилище в сети: части везёт Elemenx.Network.Transfer поверх транспорта приложения (или функции «часть, действие → транспорт»). Какая часть запрошена — дело приложения, а не сети: у транспорта одного запроса (XHR) одна часть — один запрос по его URL, методу и заголовкам (Read берёт байты ответа, 404 — части нет; Write отправляет байты); у транспорта сообщений (WebSocket, канал WebRTC, окно) — сообщения приложения {Planet: {Action, ID, Part, Error}, Bytes}, которые Transfer пакует как структурные данные; ответы (Result, Error) и новости (Changed — для Watch) приходят через TransferReceiver. Key(part) — ключ части, Path(part) — её путь в файле планеты: имена файлов есть только у файла.
