# Сборки

`elemenx build` превращает проект в то, что запускают сервер, файл, другой сайт, браузер или система. Сборка любого вида берёт только то, что использует приложение, встраивает его шаблоны и стили и минифицирует результат.

| Сборка | Команда | Что получается |
| --- | --- | --- |
| Сайт | `elemenx build` | `dist/` для любого статического сервера |
| Один файл | `elemenx build --single` | один `index.html`, работающий с сервера или из `file://` |
| Виджет | `elemenx build --widget` | один изолированный `widget.js` для страницы другого сайта |
| Расширение браузера | `elemenx build --extension` | расширения Chrome, Edge и Firefox, упакованные для магазинов |
| Нативные программы | `elemenx build --native` | программа для компьютера (Electron), программы Android и iOS (Capacitor) |

## Сайт

`dist/` содержит `index.html` (копию из проекта), `elemenx.js` и `app.js`: бандл графа приложения (`Elemenx.Bundle({...})`, см. [Ресурсы и бандлы](/guide/resources)), а за ним исходный `app.js`. Остальные публичные файлы проекта (изображения, шрифты, данные) копируются; исходники, `node_modules` и файлы пакета — нет. `elemenx serve` обслуживает его так, как в производстве.

## Что сборка опускает

- **Компоненты**, которые приложение не отрисовывает: сборка идёт по тегам его шаблонов, затем по шаблонам взятых компонентов.
- **Сервисы, охранников и директивы**, которых оно не называет: она сохраняет названные в коде в кавычках (`$Service('Toast')`, `Guards: ['SignedIn']`) и директивы, которые его шаблоны ставят на элементы, а также то, чем пользуются они.
- **Файлы библиотек**: из пакетов (эмодзи, города, наборы иконок, игровые темы) сборка в папку копирует те, что приложение использует, со всеми их языками (см. ниже).
- **Фразы библиотек**: в их словарях остаются фразы, которые называет код сборки, — по ключу или по его началу.
- **Части фреймворка**: Router, Network, Storage, Events, Messaging, WebWorker и ServiceWorker остаются, только если код сборки их использует (`$Router`, `$Network`, `$Storage`, `$Events` или `$OnEvent`, `$Messaging` или `$OnMessage`, `$WebWorker`, `$ServiceWorker`, `Elemenx.Network`...). Messaging сохраняет Events; приложение с воркерами сохраняет весь фреймворк, потому что их скрипты — файлы, которые сборка не читает.

Сборка сообщает, что опустила. Имя, собранное во время выполнения (`$Service(name)`), не выдаёт использования: назовите его где-нибудь в кавычках или собирайте с `--full`, который сохраняет весь фреймворк и все файлы библиотек.

## Иконка приложения

`Icon: '/icon.png'` в `elemenx.config.js`, квадратный PNG проекта (1024 пикселя), — иконка везде: иконка страницы и Apple, иконки PWA, ICO, ICNS и PNG программ для компьютера с их установщиками, иконки Android и iOS. `Icons: {Favicon, Windows, Mac, Linux, Android, IOS}` даёт платформе свой файл.

## Заставка

`Splash: true` в `elemenx.config.js` (или `{Image, Background, Color, Text, Spinner, MinTime, Timeout}`, или `splash.html` в проекте) показывает заставку с первой отрисовки страницы, пока первое приложение не будет готово: сборка кладёт её в начало body, без скрипта, и `elemenx dev` отдаёт её тоже. `Elemenx.Splash.Hold()` держит её до `Elemenx.Splash.Hide()` — для приложения, которое сначала загружает данные. Окно программы для компьютера и экран телефона при запуске программы берут её фон.

## Устанавливаемое приложение (PWA)

`PWA: true` в `elemenx.config.js` (или `{Name, ShortName, Description, Icon, Theme, Background, Display, Start, Offline}`) делает сборку сайта устанавливаемой: `manifest.webmanifest`, на который ссылается страница, и — с `Offline` (по умолчанию) — service worker, который хранит файлы сборки, так что приложение работает без сети. Установку приложение предлагает когда само решит: `Elemenx.Install.Available()` сообщает, что браузер может его установить, `Elemenx.Install.Prompt(callback)` показывает его окно, `Elemenx.Install.Manual()` верно в Safari на iOS, где устанавливают через меню «Поделиться».

## Выражения кодом

`--precompile` записывает выражения шаблонов в сборку функциями (`Elemenx.Expressions({...})`), чтобы она работала на странице, чья Content Security Policy запрещает `eval`. Сборщик читает тексты `$Template` (и суммы текстов), файлы `$TemplateURL`, `Elemenx.Template(name, text)` и элементы `<template>` страницы; шаблон, созданный во время выполнения, не читается, и его выражения на такой странице выбрасывают ошибку. Расширения и нативные программы всегда предкомпилируют.

## Один файл

`--single` (или `Single: true`) кладёт фреймворк, приложение, его шаблоны и стили и его библиотеки (их таблицы стилей, спрайты и данные через `Elemenx.Resource`) в один минифицированный `index.html`. Страница должна загружать `elemenx.js` и `app.js` через `<script src>`: они займут их места. Изображения и другие файлы копируются рядом.

Пакеты библиотеки (эмодзи, города, наборы иконок, игровые темы) попадают внутрь, только когда приложение их использует: текст из их `Uses` в его коде или шаблонах (`'Emoji'`, `CityInput`, `brands:`, `'fantasy'`), а пакет языка — когда это `lang` у `<html>`. `--packs emoji,brands` (или `all`) добавляет пакеты, использование которых код показать не может.

Файл работает с любого статического сервера и из `file://`, с ограничениями: из файла не запускаются воркеры; service worker требует собственного скрипта; маршрутизатор держит маршрут в памяти (используйте `$Router: {Mode: 'hash'}` для маршрутов в URL); Content Security Policy должна разрешать встроенные скрипты и стили.

## Виджет

`--widget` (или `Widget: true`) собирает один изолированный `widget.js` с фреймворком, используемыми библиотеками и приложением:

- окно не получает `Elemenx`: у виджета своя копия, а на странице может быть Elemenx любой версии;
- приложение отрисовывается в shadow root своего `$Mount` (если не `$Shadow: false`): стили страницы и виджета не пересекаются;
- `lang`, `dir` и тема уходят на хост виджета, а не на страницу.

Страница загружает его через `<script src="widget.js"></script>` и даёт ему элемент монтирования (`<div id="widget"></div>`). URL внутри виджета читаются относительно страницы, поэтому давайте им абсолютные адреса; виджет не запускает воркеров.

## Расширение браузера

`--extension` создаёт расширение Manifest V3 в `dist/extension/chrome` (Chrome, Edge, Vivaldi) и `dist/extension/firefox`, с `chrome.zip` и `firefox.zip`. `--surface` (или `Extension.Surface`): `popup` (окно кнопки, по умолчанию), `tab` (собственная вкладка) или `side` (боковая панель Chrome, сайдбар Firefox). Манифест берёт имя, описание и версию из `package.json`; `Extension.ID` (Firefox), `Extension.Icons` и `Extension.Manifest` (ключи, добавляемые в оба манифеста: `permissions`, `host_permissions`...) дополняют его. Страница расширения не выполняет встроенных скриптов, а её маршрутизатор держит маршрут в памяти.

## Нативные программы

@block 1

- **Компьютер**: `dist/native/desktop` содержит приложение, `main.js`, `preload.js` и настройки; с установленными Electron и упаковщиком программа для системы появляется в `dist/native/desktop-bin` (`Native.Desktop.Platform` и `Arch` выбирают другую). Окно загружает приложение по собственной схеме (`app://bundle/`), у страницы нет Node, и с системой она общается через мост, которым пользуется сервис `Platform` из ElemenxUI: окна, диалоги, меню, трей, глобальные сочетания клавиш, автозапуск, ссылки собственной схемы (`Native.Desktop.Protocol`), питание, обновления. `Native.Desktop.Frame: false` позволяет приложению рисовать свою строку заголовка. Программа — это папка (её исполняемому файлу нужны файлы рядом): `Native.Desktop.Targets: ['zip', 'installer', 'portable']` делает из неё zip, установщик и портативную программу в `dist/native/desktop-dist` (установщик и портативную — через electron-builder) и оставляет только языки Chromium, на которых говорит приложение (`Native.Desktop.Languages`, `all` — все).
- **Своя программа для Android**: `elemenx build --native android-library` делает модуль Gradle (`dist/native/android-library/elemenx`) с приложением в его assets и `ElemenxView` — представлением, которое ваша программа на Java или Kotlin показывает и которому отвечает (`view.handle(name, args -> result)`, `view.emit(name, value)`); без Capacitor (см. README рядом).
- **Мобильные**: проект становится проектом Capacitor; сборка записывает приложение в `dist/native/mobile`, добавляет установленные платформы Android и iOS и копирует его в них; программы собирают Android Studio и Xcode (`npx cap open android`).

Настройки — `Native.Desktop` (`Name`, `Version`, `Width`, `Height`, `Features`, `Protocol`, `Update`, `Frame` (`system`, `hidden`, `none`, `transparent`), `Material`, `Targets`, `Languages`...) и `Native.Mobile` (`AppID`, `Name`, `Platforms`) в `elemenx.config.js`.

## Несколько приложений

Проект с несколькими графами приложений (`Shop/`, `Admin/`, у каждого свой `index.js`) собирает все графы, которые объявляет его `app.js`, в один бандл; `Applications: ['Shop', 'Admin']` (или `--applications`) называет их, `--application Shop` собирает одно. Два графа не могут объявлять одно имя одного типа.

## Фреймворк

`npm run dist` в репозитории Elemenx собирает файлы дистрибутива в `dist/` пакета: `elemenx.js` и `elemenx.min.js`, `elemenx-ui.js` (ElemenxUI со всем встроенным, кроме пакетов), скрипт для каждого пакета (`elemenx-ui.emoji.js`, `elemenx-ui.cities.js`...), `elemenx.all.js` (оба в одном файле), `elemenx-ui/` (ElemenxUI файлами) и `manifest.json` (размеры и хеши целостности каждого файла). Им не нужны ни сборка, ни сервер.

## Образ Docker

`elemenx build --docker` собирает сайт и пишет рядом `Dockerfile` и `nginx.conf` для `nginx:alpine`: gzip для текста, любой путь, который не файл, получает `index.html` (маршруты роутера переживают перезагрузку), страница и воркер PWA никогда не кэшируются, заголовки безопасной страницы и проверка здоровья по `/healthz`. Если установлен `docker`, собирается и образ, названный по `package.json` (`my-shop:1.4.2`): `docker run -p 8080:80 my-shop:1.4.2` запускает его. `Docker` в `elemenx.config.js` задаёт `Image` (своё имя или `false`, чтобы получить только файлы) и `Headers` (`Content-Security-Policy`...). Без `docker` сборка говорит, как собрать образ потом; с `--strict` — падает.

## Несколько целей сразу

`Build.Targets` в `elemenx.config.js` перечисляет, что собирает `npx elemenx build`, — всё одной командой:

@block 2

Цели: `web`, `single`, `widget`, `extension`, `desktop`, `mobile`, `android-library` и `docker`. Одна цель попадает туда же, куда её отдельная сборка; несколько — каждая в свою папку: `dist/web`, `dist/single`, `dist/widget`, `dist/docker`, а `dist/extension` и `dist/native/<платформа>` как обычно. `--target web,docker` собирает только их, а опция режима (`--single`, `--extension`...) — только его. Цель, которая не собралась, останавливает сборку и называет себя.
