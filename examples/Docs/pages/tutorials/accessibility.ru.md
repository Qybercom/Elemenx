# Доступное приложение

Каждый пятый человек живёт с инвалидностью; у каждого однажды бывает сломанная рука, яркое солнце на экране телефона или медленная сеть. Доступное приложение работает с одной клавиатурой, со скринридером, при большом масштабе, в высоком контрасте и без анимации. Почти всё это бесплатно, если заложено с самого начала, и дорого, если добавлять потом.

Чему вы научитесь: что ElemenxUI делает за вас, а что остаётся вашим: порядок заголовков и ориентиров, имена элементов управления, фокус, сообщения, которые зачитываются, цвет и движение и как всё это проверить.

## 1. Что дают компоненты

Компоненты ElemenxUI для этого и сделаны, и тесты проекта это проверяют:

- `Field` называет свой контрол по своему `Label` (`aria-labelledby`) и помечает его обязательным (`aria-required`); его ошибка — `role="alert"`, который зачитывается при появлении.
- `Dialog` и `Drawer` — элементы `<dialog>`: фокус уходит внутрь, остаётся внутри и возвращается на кнопку, которая их открыла; Escape их закрывает.
- `Select`, `Menu`, `Tabs`, `RadioGroup`, `Tree` и другие следуют шаблонам WAI-ARIA Authoring Practices: их роли, состояния (`aria-expanded`, `aria-selected`) и клавиши (стрелки, Home, End, набор буквы).
- `ToastHost` — живой регион: уведомление зачитывается, не забирая фокус.
- Фокус всегда виден (`:focus-visible`), анимации останавливаются при `prefers-reduced-motion`, а тема `contrast` повышает весь контраст (`this.$Service('Theme').Use('contrast')`).
- В языке справа налево компоненты зеркалятся, а их стрелки сохраняют смысл (`Elemenx.Locale.Key`).

Ничего из этого не поможет, если страница вокруг них — куча `div`.

## 2. Страница: ориентиры и заголовки

```html
<header>...</header>
<nav aria-label="Pages">...</nav>
<main>
	<h1>Orders</h1>
	<section aria-labelledby="open-title">
		<h2 id="open-title">Open</h2>
		...
	</section>
</main>
<footer>...</footer>
```

Скринридер перечисляет ориентиры (`header`, `nav`, `main`, `footer`) и заголовки и прыгает между ними: так страницу читают, не видя её. Один `h1` на страницу, уровни без пропусков. Роутер меняет страницу без загрузки: дайте каждому маршруту `$Title` (он становится заголовком вкладки, который зачитывается) и переведите фокус на `h1` новой страницы, чтобы чтение начиналось с неё, а не со ссылки, которую нажали:

```js
$OnReady: function () {
	var heading = this.$Element().querySelector('h1');

	heading.setAttribute('tabindex', '-1');
	heading.focus();
}
```

## 3. У каждого элемента управления есть имя

Кнопка с одной иконкой ничего не говорит скринридеру:

```html
<!-- Read as "button" -->
<button type="button" (click)="Removed"><Icon Name="delete" /></button>

<!-- Read as "Remove Buy milk, button" -->
<button type="button" [attribute.aria-label]="'Remove ' + item.Title" (click)="Removed"><Icon Name="delete" /></button>
<Button Icon="delete" Title="Remove" (click)="Removed" />
```

`Input` вне `Field` берёт имя из `Label`; ссылка говорит, куда ведёт («Прочитать отчёт», а не «нажмите здесь»); у картинки, которая что-то сообщает, есть `alt`, а у украшения — `alt=""`.

## 4. Клавиатура

- Используйте настоящий элемент: `<button>` для действия, `<a href>` для места. `div` с `(click)` не достижим через Tab и не нажимается Enter.
- Порядок Tab — это порядок разметки: раскладывайте страницу через CSS, а не двигая фокус через `tabindex`. `tabindex="0"` делает элемент достижимым; положительное число — никогда.
- Всё, что открывается мышью, открывается клавиатурой и закрывается Escape. Всё, что происходит при наведении, происходит и при фокусе.
- Сочетания клавиш (`*hotkey`, сервис `Hotkeys`) — помощь, а не единственный путь, и сочетание из одной буквы должно отключаться: оно срабатывает, пока человек диктует текст голосом.

## 5. Сообщения, которые слышно

Изменение, которое появляется в другом месте страницы (сохранённая форма, счётчик, ошибка сервера), не видит тот, кто не видит. Поместите его в живой регион:

```html
<p class="status" role="status">{{Saved ? 'Saved' : ''}}</p>
<div class="elemenx-callout danger" role="alert" *if="Error">{{Error}}</div>
```

`role="status"` (вежливый) ждёт паузы; `role="alert"` перебивает — только для ошибок. Регион должен быть на странице до того, как изменится его текст: регион, добавленный вместе с текстом, часто не зачитывается. Уведомление (`this.$Service('Toast').Show(...)`) зачитывается за вас.

## 6. Цвет, размер и движение

- Тексту и его фону нужен контраст 4,5 к 1 (3 к 1 для крупного текста и для границ элементов управления). Токены ElemenxUI держат его в обеих схемах; ваш собственный цвет тоже должен.
- Никогда не сообщайте что-то одним цветом: ошибка красная, но у неё есть текст и иконка; у обязательного поля есть пометка и `aria-required`.
- Страница работает при масштабе 200% и ширине 320 CSS-пикселей без горизонтальной прокрутки. Размеры в `rem` следуют размеру шрифта, который выбрал человек.
- Движение останавливается при `prefers-reduced-motion: reduce`, и ничего не мигает чаще трёх раз в секунду.

## 7. Проверка

- **Клавиатурой**: уберите мышь и выполните каждую задачу страницы. Фокус всегда виден? Tab идёт в разумном порядке? Из каждого диалога можно выйти?
- **Скринридером**: NVDA в Windows (бесплатно), VoiceOver в macOS и iOS (Cmd+F5), TalkBack в Android. Прослушайте одну страницу с начала, потом по заголовкам и по ориентирам.
- **Автоматически**: axe находит примерно треть проблем (контраст, имена, роли). С Playwright:

```js
import AxeBuilder from '@axe-core/playwright';

test('the page has no violations axe can find', async function ({ page }) {
	await page.goto('/');

	expect((await new AxeBuilder({page: page}).analyze()).violations).toEqual([]);
});
```

- **В тестах, которые у вас уже есть**: ищите элементы так, как ищет человек, — `getByRole('button', {name: 'Save'})` и `getByLabel('Email')`. Тест, находящий контрол по роли и имени, упадёт, когда контрол их потеряет: он даром проверяет доступность. Туториалы этой справки проверяются именно так.
